# Registro operacional privado — modelo

Use uma cópia para cada deploy, rollback, incidente, rotação ou restauração. Não inclua pacientes, tokens, mensagens, senhas, chaves ou logs brutos. Evidência ausente fica **não verificada**.

| Campo | Preenchimento |
| --- | --- |
| ID, tipo e data/hora com fuso | PENDENTE |
| Operador, substituto, aprovador e contatos acionados | PENDENTE |
| Serviços/clínicas afetados, sem dados pessoais | PENDENTE |
| Revisão Git e `APP_VERSION` anterior/nova | PENDENTE |
| Migrations: responsável, versão e resultado | PENDENTE |
| Backup banco/anexos, checksum e último dado | PENDENTE |
| Fatos, impacto e hipóteses separados | PENDENTE |
| Linha do tempo: detecção, contenção, recuperação | PENDENTE |
| Smoke tests: login, permissão, isolamento, exportação, rotas | PENDENTE |
| Health, TLS, portas, alertas e evidências redigidas | PENDENTE |
| Rollback/restauração: ponto, tempo, perda real | PENDENTE |
| Comunicação: aprovador, destinatários, hora e próxima atualização | PENDENTE |
| Chaves rotacionadas: identificadores, teste, revogação | PENDENTE |
| Causa, ações, responsáveis e próxima revisão | PENDENTE |
| Próximo ensaio de restauração | PENDENTE |
